# Agent Note: 无未分组会话 —— 每个会话都归属一个工作区

Status: rejected — adoptSessions 路径已经实现此目标，无需新增表面

English | [中文](2026-09-05-no-ungrouped-sessions.zh.md)

## Problem

产品表面在侧边栏里有一个可见的 `Ungrouped`（未分组）桶
（[apps/web](../../../../apps/web) 的 e2e 测试大量断言它）。只要会话在创建时没有显式的工作区归属，自动生成的对话就会落入该桶。这正是运营方声明的不允许状态：不应产生未分组的工作区，也不应产生未分组的自动生成对话。

一个会话变成未分组有许多创建路径，而非单一路径。GUI 的“新建会话”流程会物化一个工作区并 attach 会话，但其余路径完全绕开了该流程：

- `session.create({ cwd })` 解析 `cwd` 并创建会话，但从不调用 `attachSession`，即使该目录已被某工作区注册（[commands.ts](../../../../packages/api/session-controller/src/commands.ts)）。
- `ctx.agents.create({ meta: { cwd } })` 被子代理、ACP、webhook、headless、SDK、钩子、定时任务、goal 等调用方直接使用，均不 attach。
- `fork` 仅在 `forkWorkspace` 解析出工作区时才 attach，可能为 `undefined`（[commands.ts](../../../../packages/api/session-controller/src/commands.ts)）。
- `cwd` 缺失、无效、被移动或删除时，没有可归组的目录。
- 删除工作区注册后，其会话按设计变为未分组。

会员不变量阻断了朴素保证。`attachSession` 会用工作区路径重新校验会话头中存储的 `cwd`，而会员要求“在成员列表中”与“规范化的 `cwd` 与工作区路径匹配”两者同时成立（[types.ts](../../../../packages/workspace/workspace/src/types.ts)）。因此没有任何 `cwd` 的会话在结构上就不可能归属任何工作区。要保证“无未分组”，需要两套机制而非一套。

## Proposal

为工作区注册表新增一个**创建即收养（adopt-on-create）**策略，使任何会话无论由谁创建都恰好落在一个工作区内。默认关闭，因此现有所有组合与测试保留当前的未分组行为，直到某个 profile 显式开启。

### 策略面

`WorkspaceRegistry` 新增一个可选的 `Config` 字段：

```ts
interface Config {
  /** 收养每个已创建的会话到某一工作区；默认 `false`。 */
  readonly adoptSessions?: boolean
}
```

当 `adoptSessions` 为 `false`（默认）时，注册表行为与今天完全一致。为 `true` 时，创建与引导遵守下面的保证。

### 创建时的收养顺序

一个会话在可观察（`session/created` 事件）时立即被收养，顺序如下：

1. 读取会话头 `cwd`，用注册表的 `realpath` 规范进行规范化。
2. 有效目录：解析拥有该规范路径的工作区并 `attachSession`（幂等）。若无工作区拥有它，则按该路径 `create` 一个工作区（标题为 `basename`）并 attach。这是运营方接受的自动创建行为。
3. 无可归组的 `cwd`（缺失、无效、被移动或删除）：注册表让会话保持未分组并记录日志，绝不伪造会员。一个会话只有在存储的 `cwd` 等于工作区路径时才属于该工作区，而该头部 `cwd` 在创建时设定且不可变，因此无 cwd 会话在结构上不可能 attach。

这一单一监听器覆盖所有创建路径，因为无论由哪个调用方创建，每个会话都会发出 `session/created`。任何 agent、工具或子代理代码都不需要知道工作区的存在。

### 启动对账

一次性引导被扩展，仍仅读头部，并对其对现有会话幂等。当 `adoptSessions` 开启时，历史引导完成后，注册表遍历每个已存储与会话中的头部并重新应用收养顺序：已出现在匹配工作区成员列表中的会话直接跳过；拥有有效规范 cwd 但无工作区拥有的会话，创建一个工作区并 attach；其余保持未分组。`initialized` 标记最后写入，使被中断的对账可以安全恢复，与现有引导契约一致。

### 不可归组 cwd 的边界

运营方第三个决策——无 cwd 会话回退到默认工作区——是这份设计**未**实现的一条。会员规则要求会话存储的 `cwd` 等于工作区路径，而该 `cwd` 在创建时设定且不可变，因此无 cwd 的会话要么重写头部要么放宽不变量才能 attach 到任何工作区。在创建时赋予一个默认 `cwd` 必须注入到 agent-create 边界，而那是核心且对模型可见的层，不是宿主侧工作区注册表能影响的。GUI 的 `session.create` 路径已经为每个会话解析出 `cwd`，因此真实的自动生成会话总是携带一个；真正无 cwd 的会话来自深层 `agents.create` 调用方，并作为有记录的最后一招保持未分组，绝不伪造会员。

## Package boundaries

| 层 | 改动 |
|---|---|
| `packages/workspace/workspace` | `Config` 字段；`session/created` 收养监听器；启动对账；复用 `create`/`attachSession` |
| `packages/client/ui-workspace` | `watchNavigation` 不再在进入时自动创建并打开对话：仅恢复真实会话选择，否则保持新建会话空态，只有显式 `startSession` 或首条消息才创建 |
| `packages/api/session-controller` | `create`/`fork` 保留其显式 attach；无行为变更，仅确认不会重复 attach |
| `apps/web` | 当组合启用收养时，`Ungrouped` 桶在空桶时收敛；那些以未分组为种子的 e2e 断言仍有效，因为它们在关闭收养时运行 |

工作区注册表是宿主侧且对模型不可见，因此宿主策略不增加任何 prompt、工具或请求 token。客户端改动停止左侧菜单的自动对话生成；两者共同兑现运营方的结果。

## Alternatives considered

**仅手动收养（“归入某工作区”的操作）。** 被拒绝：它只在用户主动操作后移除可见桶，而运营方要求的是自动生成的对话永不落到未分组，而非之后可修复。

**只收养到已注册工作区，绝不创建。** 被拒绝：许多自动生成会话运行在没有任何注册工作区的目录里，于是仍会未分组；运营方已接受自动创建。

**为遗留会话合成一个单独的 “Ungrouped” 工作区。** 被拒绝：它命名了运营方想要消除的同一个概念，而且仍会为那些自身没有 cwd 的会话凭空发明一个工作区。

**放宽会员不变量，使无 cwd 会话能 attach 到默认工作区。** 被拒绝：会员是一个在规范 `cwd` 上声明的单所有者不变量，只因一个桶而放弃它会削弱整个注册表的所有权保证。

**持续地从会话 cwd 派生工作区**（产品流笔记已拒绝的流程）。再次被拒绝：它无法表示空工作区、稳定名称或显式顺序，并会无记录地自动收养所有非工作区调用方。

## Acceptance criteria

- 在 `adoptSessions` 关闭（默认）时，所有现有工作区、会话与快照行为不变；当会话无归属时 `Ungrouped` 桶仍会出现。
- 在 `adoptSessions` 开启时，`session.create({ cwd })` 为已注册目录创建的会话会 attach 到该工作区；为未注册目录创建的会话会创建工作区并 attach。
- 由 `ctx.agents.create` 以有效 `cwd` 创建的会话会被收养，而无需该调用方改动。无可归组 `cwd` 创建的会话保持未分组并记录日志；绝不伪造会员。
- 启动对账会把每个已有有效 cwd 的会话分配到某个工作区（已存在或新建），并在多次重启间幂等。
- 不为非真实存在的目录创建工作区记录；创建仍会拒绝不存在的路径。
- 删除工作区仍不删除其目录、文件或会话日志；那些会话会像今天一样重新进入 `Ungrouped` 桶。
- 无 key 可运行快照覆盖默认关闭路径不变以及收养开启的创建与对账路径；REAL 组合测试覆盖子代理与无 cwd 收养场景。

## Risks

最大的改动是运营方已接受的自动创建：会话目录现在会在没有显式用户创建的情况下物化一个工作区记录。这把工作区记录与会话活动绑定，意味着再次添加一个已删除目录时，一旦有会话再次于其中运行，就不再是全新空组。收养监听器是宿主侧并通过注册表操作链串行化，因此开启时每个创建的会话会增加一次写入；默认关闭路径不增加任何写入。

无 cwd 会话的默认工作区回退被有意地未实现。无任何可归组 `cwd` 的会话保持未分组并记录日志，因为不可变的头部 `cwd` 与单所有者会员规则让任何其他结果要么放宽不变量，要么把一个默认 cwd 注入耦合进核心创建路径。大多数自动生成的会话都携带 `cwd`——GUI 的 `session.create` 路径为每个会话解析一个——因此这条边界很窄，但它确实是对最初“默认工作区”意图的一个真实缺口。

开启时对账遍历会触及每个已存储头部。它仅读头部且幂等，但在非常庞大的历史上这是一次额外的启动遍历；默认关闭路径完全跳过它。
